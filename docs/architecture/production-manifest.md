# Production manifest specification

**Status:** Proposed schema v1  
**Purpose:** Canonical, versioned representation of a Renderhaus long-video production

## 1. Why a manifest

A long film cannot be reconstructed reliably from an agent transcript. It needs explicit hierarchy,
entities, dependencies, asset provenance, evaluation results, costs, approvals, and timeline state.
MovieBench formalizes movie/scene/shot hierarchy for long-video data
([Wu et al., 2025](https://openaccess.thecvf.com/content/CVPR2025/html/Wu_MovieBench_A_Hierarchical_Movie_Level_Dataset_for_Long_Video_Generation_CVPR_2025_paper.html));
VideoMemory represents persistent characters, props, and backgrounds as evolving entity state
([Zhou et al., 2026](https://arxiv.org/abs/2601.03655)); and EntityBench uses per-shot schedules for
characters, objects, and locations across long recurrence gaps
([He et al., 2026](https://arxiv.org/abs/2605.15199)). The Renderhaus manifest combines these proven
representations with execution and editorial metadata required by the product.

```text
│       ├── Take[]
│       └── Evaluation[]
├── AudioPlan

│   └── TimelineItem[]
├── Asset[]
├── CostLedger
├── Approval[]
└── Output[]
```

## 3. Identity and revision rules

- IDs are immutable UUIDv7 values generated by application code.
- Every aggregate has `schema_version`, `revision`, `created_at`, and `updated_at`.
- User-visible edits create a new production revision; attempts and events remain append-only.
- A locked entity or shot references exact asset and spec revisions.
- Approval records bind to production revision, artifact checksum, estimate, and approver.
- Assets are immutable and content-addressed by SHA-256.
- Deleting a logical entity tombstones it; referenced asset deletion is asynchronous and guarded.
- Times are UTC ISO-8601; timeline positions are integer frames plus rational frame rate, avoiding
  cumulative floating-point drift.

## 5. Creative brief

```python
class CreativeBrief(BaseModel):
    objective: str
    audience: str
    target_duration_frames: int
    frame_rate: Fraction = Fraction(24, 1)
    aspect_ratio: Literal["16:9", "9:16"]
    narrative_mode: Literal["brand", "explainer", "documentary", "mini_story", "mood"]
    visual_direction: str
    audio_direction: str
    required_elements: list[str]
    forbidden_elements: list[str]
    reference_asset_ids: list[UUID]
    budget_mode: Literal["draft", "balanced", "premium"]
    budget_ceiling_usd: Decimal
    approval_policy: ApprovalPolicy
    delivery: DeliverySpec
```

The model proposes defaults, but deterministic validation enforces duration, frame rate, budget,
and provider-supported formats.

## 6. Treatment and hierarchy

### Treatment

- Logline and audience promise.
- Beginning, development, payoff.
- Beat list with purpose, information, emotion, and duration weight.
- Narrative facts that must be established and resolved.
- Narration/dialogue draft.
- Global pacing curve and audio arc.

### Scene

```python
class Scene(BaseModel):
    id: UUID
    ordinal: int
    title: str
    dramatic_purpose: str
    location_id: UUID
    time_state: str
    target_duration_frames: int
    continuity_state_in: dict[UUID, UUID]
    continuity_state_out: dict[UUID, UUID]
    shot_ids: list[UUID]
    locked: bool
```

### Shot

```python
class Shot(BaseModel):
    id: UUID
    scene_id: UUID
    ordinal: int
    purpose: str
    target_duration_frames: int
    shot_size: str
    camera_angle: str
    camera_motion: str
    lens_language: str
    composition: str
    action: str
    dialogue_cue_ids: list[UUID]
    sound_cue_ids: list[UUID]
    entity_appearances: list[EntityAppearance]
    screen_direction: str | None
    transition_in: TransitionIntent
    transition_out: TransitionIntent
    start_keyframe_asset_id: UUID | None
    end_keyframe_asset_id: UUID | None
    selected_take_id: UUID | None
    state: ShotState
    locked: bool
```

MovieAgent’s scene and shot planning plus Camera Artist’s focus on narrative progression across
adjacent shots support storing shot purpose, camera language, and transition intent explicitly
([MovieAgent](https://arxiv.org/abs/2503.07314),
[Camera Artist](https://arxiv.org/abs/2604.09195)). These are not decorative prompt fields: they are
criteria the evaluator can test.

## 7. Continuity entities and state

```python
class ContinuityEntity(BaseModel):
    id: UUID
    kind: Literal["character", "location", "prop"]
    canonical_name: str
    invariant_traits: list[str]
    mutable_state_schema: dict
    canonical_asset_ids: list[UUID]
    negative_constraints: list[str]
    provenance: Provenance

class EntityState(BaseModel):
    id: UUID
    entity_id: UUID
    effective_from_shot_id: UUID
    state: dict
    verified_asset_ids: list[UUID]
    supersedes_state_id: UUID | None

class EntityAppearance(BaseModel):
    entity_id: UUID
    required: bool
    state_id: UUID
    narrative_role: str
    spatial_relation: str | None
    reference_asset_ids: list[UUID]
```

The split between invariant traits and mutable state prevents an injury, costume change, weather
shift, or prop transfer from either being forgotten or incorrectly applied to earlier shots.
VideoMemory explicitly updates entity memory after story-driven changes while preserving identity
([Zhou et al., 2026](https://arxiv.org/abs/2601.03655)).

## 8. Generation specification and attempts

### Provider-neutral generation spec

```python
class ShotGenerationSpec(BaseModel):
    shot_id: UUID
    shot_revision: int
    duration_frames: int
    frame_rate: Fraction
    aspect_ratio: str
    resolution: str
    prompt: str
    negative_prompt: str | None
    reference_inputs: list[ReferenceInput]
    native_audio: bool
    provider_requirements: set[str]
    policy_snapshot_id: UUID
    memory_pack_id: UUID
```

`ReferenceInput` has role (`character`, `location`, `prop`, `start_frame`, `end_frame`,
`motion`, `audio`, `prior_task`), asset/task identifier, strength when supported, and provenance.
This matches the range of official Seedance reference modalities and Veo frame/reference controls
([BytePlus](https://docs.byteplus.com/en/docs/ModelArk/1520757),
[Google Veo](https://ai.google.dev/gemini-api/docs/veo)).

### Attempt

```python
class GenerationAttempt(BaseModel):
    id: UUID
    shot_id: UUID
    ordinal: int
    idempotency_key: str
    provider: str
    model: str
    model_version: str | None
    spec_checksum: str
    provider_task_id: str | None
    state: AttemptState
    submitted_at: datetime | None
    completed_at: datetime | None
    estimated_cost_usd: Decimal
    actual_cost_usd: Decimal | None
    error_class: str | None
    asset_id: UUID | None
```

Attempts are append-only. A “retry” creates a new attempt only when policy chooses a new generation.
Retries of the same provider submission activity reuse the same attempt and idempotency key.

## 9. Assets and takes

```python
class Asset(BaseModel):
    id: UUID
    sha256: str
    media_type: str
    role: str
    storage_uri: str
    bytes: int
    width: int | None
    height: int | None
    duration_frames: int | None
    frame_rate: Fraction | None
    audio_channels: int | None
    verification_state: str
    provenance: Provenance

class Take(BaseModel):
    id: UUID
    shot_id: UUID
    attempt_id: UUID
    video_asset_id: UUID
    representative_frame_asset_ids: list[UUID]
    evaluation_ids: list[UUID]
    disposition: Literal["candidate", "selected", "rejected", "fallback"]
```

Representative frames are selected semantically and aesthetically rather than sampled blindly.
StoryMem reports benefits from semantic keyframe selection plus aesthetic filtering for stable
memory ([Zhang et al., 2025](https://arxiv.org/abs/2512.19539)). Only selected, verified takes can
contribute representative frames to canonical memory.

## 10. Evaluation schema

```python
class Evaluation(BaseModel):
    id: UUID
    subject_type: Literal["asset", "take", "transition", "scene", "production"]
    subject_id: UUID
    evaluator: str
    evaluator_version: str
    rubric_version: str
    scores: dict[str, float]
    gates: dict[str, bool]
    defects: list[Defect]
    evidence_asset_ids: list[UUID]
    recommendation: Literal["accept", "repair", "fallback", "review", "reject"]
    confidence: float
```

Scores remain dimensional. VBench demonstrates the diagnostic value of separating qualities such
as identity, motion, flicker, and spatial relations
([Huang et al., 2024](https://openaccess.thecvf.com/content/CVPR2024/html/Huang_VBench_Comprehensive_Benchmark_Suite_for_Video_Generative_Models_CVPR_2024_paper.html)).
DirectorBench likewise argues that a single aggregate hides workflow-specific failures
([Chen et al., 2026](https://arxiv.org/abs/2605.30090)). The policy computes release gates from
individual scores; a weighted average cannot conceal a critical continuity defect.

## 11. Timeline and audio

```python
class Timeline(BaseModel):
    id: UUID
    revision: int
    frame_rate: Fraction
    duration_frames: int
    tracks: list[Track]
    render_spec: RenderSpec

class TimelineItem(BaseModel):
    id: UUID
    track_id: UUID
    asset_id: UUID
    source_in_frame: int
    source_out_frame: int
    timeline_in_frame: int
    timeline_out_frame: int
    transition_in: Transition | None
    transition_out: Transition | None
    transforms: list[DeterministicTransform]
```

Track roles are `picture`, `dialogue`, `narration`, `onscreen_sfx`, `ambience`, `music`, `caption`,
and `overlay`. ReelWave’s separate modeling of synchronized on-screen and complementary off-screen
audio supports this role distinction ([Wang et al., 2025](https://arxiv.org/abs/2503.07217)).

Timeline invariants:

- No unintended picture gaps or overlaps.
- All source ranges fit their assets.
- Transition overlap is reflected exactly in total duration.
- Dialogue/narration cues are not truncated without an explicit override.
- Caption cues fit the timeline and do not overlap illegally.
- Final duration matches delivery spec.

## 12. Cost, policy, and approval

```python
class ProductionPolicy(BaseModel):
    max_total_cost_usd: Decimal
    max_generation_attempts_per_shot: int = 3
    max_critic_repairs_per_shot: int = 2
    max_parallel_paid_tasks: int = 4
    hero_candidate_count: int = 2
    default_candidate_count: int = 1
    auto_accept_thresholds: dict[str, float]
    human_review_thresholds: dict[str, float]
    allowed_providers: list[str]

class Approval(BaseModel):
    id: UUID
    stage: Literal["plan", "storyboard", "cost", "final"]
    production_revision: int
    artifact_checksum: str
    estimate_usd: Decimal | None
    approved_by: UUID
    approved_at: datetime
```

Material changes to duration, provider set, candidate count, locked references, or projected cost
invalidate cost approval. Agents cannot raise policy limits.

## 13. Dependency invalidation

The manifest records explicit dependency edges. Common invalidation rules:

| Change | Invalidates |
|---|---|
| Brief duration | treatment timings, scenes, shots, audio plan, timeline, cost approval |
| Character canonical asset | unlocked appearances, related memory packs, their takes/evaluations, final render |
| Shot prompt/spec | that shot’s attempts/takes, adjacent transition evaluations, scene/final evaluation, timeline render |
| Selected take | adjacent transition evaluations, scene/final evaluation, timeline render |
| Narration text | narration asset, affected shot timing, captions, audio mix, final render |
| Timeline trim only | affected transition/evaluation, audio mix, final render; not video generation |

Minimal invalidation is central to product cost. It also follows the shot-wise formulation used by
memory-based long-video systems: StoryMem and VideoMemory synthesize iteratively at shot granularity
rather than treating the complete film as one immutable sample
([StoryMem](https://arxiv.org/abs/2512.19539),
[VideoMemory](https://arxiv.org/abs/2601.03655)).

## 14. Schema migration

- Export always includes `schema_version` and producer version.
- Additive optional fields remain backward compatible within a major version.
- Semantic/invariant changes require an explicit migration and fixture.
- Workflow code records the manifest schema it began with; workflow versioning handles in-flight
  executions during deployment.
- Keep golden exports for draft, approved, partially rendered, repairing, completed, and canceled
  productions.
